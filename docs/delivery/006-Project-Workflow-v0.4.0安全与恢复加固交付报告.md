# Project Workflow v0.4.0 安全与恢复加固交付报告

## 交付结论

本轮安全与恢复加固已完成，独立契约验证结论为 **VERIFIED**。源码插件版本保持 `0.4.0`，未把本机 cachebuster 时间写回仓库。

## 已交付能力

- Doctor 只执行当前可信插件根的脚本；外部插件根仅静态检查并阻断，不执行仓库提供的同名脚本。
- Doctor 与文件快照均阻断 `.codex` 状态路径中的符号链接逃逸；调度状态使用完整结构校验。
- `workflow_state.py resume` 成为阻塞恢复的唯一入口，重新校验审批、revision、VCS 漂移和回滚门禁；低层 transition 不再允许绕过。
- 新计划使用字符串 `rollback_required`；`FULL + NONE` 或显式要求回滚时，必须同时具备 strategy、evidence 与 `VERIFIED` 三项证据。
- 调度状态增加 5 秒文件锁、递增 `state_version` 与 `--expected-version` CAS；竞争写入失败时不产生部分更新。
- 活跃或阻塞 Worker 持续占用槽位和写入范围；释放必须匹配运行身份并提供停止证据，未启动预留仅允许按 spawn failure 释放。
- `NONE` 仅支持共享工作区的互斥写入范围；文件快照检测新增、修改、删除和 POSIX mode，持久化显式排除项，越界默认以稳定非零码失败。
- 快照相对路径统一按仓库根解析；默认输出摘要，完整清单和报告型越界行为必须显式启用。
- 技能、协议与双语 README 已统一上述命令和兼容语义；不再允许在 Project Workflow 内跳过确认门禁。
- 原生子智能体小组件与图标明确归 Codex UI 管理，插件不引用图标图片；标题与阶段心跳依赖原生运行时能力，未引入守护进程。

## 迁移与兼容

- 历史计划缺少 `workflow_profile` 时继续按 `FULL` 解释；缺少 `vcs_mode` 时按 `AUTO` 读取，不因读取而改写。
- 历史计划缺少 `rollback_required` 时保留原有 profile 兼容行为。
- 历史调度状态缺少 `state_version` 时按 `0` 读取，首次成功写入后变为 `1`。
- 历史已完成 Worker 缺少运行身份时保持可读并标记为不可验证，不伪造身份。
- 历史快照缺少 mode 或 excludes 时按旧规则兼容比较；新快照记录完整新字段。
- 未知任务状态、损坏依赖、依赖环、活动范围冲突或伪造运行 Worker 均拒绝读取，不静默修复。

## 残余风险

- 文件路径防护针对正常本地并发与不可信仓库内容；未引入基于 `openat` 的内核级目录句柄沙箱，以避免为桌面插件增加不可移植的系统层复杂度。
- 调度锁使用标准库 `fcntl`，适配当前 macOS/Unix 环境；Windows 需要单独的跨平台锁实现。
- Codex 原生智能体图标、实际槽位、会话标题和可见进度投递属于宿主运行时能力，插件只能按能力存在与否安全降级。
