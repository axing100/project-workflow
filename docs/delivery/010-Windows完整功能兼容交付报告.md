# Windows 完整功能兼容交付记录（验收中）

日期：2026-09-05。分支：`feature/010-windows-support`。基线：`e35e7f9`。

本记录区分代码实现、自动验证和客户桌面宿主验收。正式版本仍为 0.5.0；
没有发布 tag、合并分支或重装个人插件。目标 0.5.1 尚未宣布交付。

## 已实现

- Windows 原生句柄相对安全 I/O、LockFileEx、有限锁等待和占用重试、原子替换，
  不依赖 WSL/fcntl，也不关闭路径检查；POSIX 保留描述符相对访问。
- 生命周期、任务状态、调度、Doctor、NONE 快照统一接入；保留 GIT/NONE、
  双语显示、审批、CAS、实际运行身份绑定及失败恢复契约。
- 原生 exe/官方 npm 布局安装入口，直接参数传递和 UTF-8；真实安装更新在隔离
  Codex 配置中验证，不改变用户个人配置或源码正式版本。
- Windows/Ubuntu/macOS CI、独立契约验收、中英平台命令和安全恢复说明。
- 独立验收额外发现旧计划显式迁移后未进入任务完成门禁；修复并保留失败断言。
  验收失败或迁移后任务状态丢失时均不得完成计划。

## 安全边界及未完成验收

Windows 状态要求固定本地磁盘；网络/UNC、云同步和跨 OS 并发未认证。
文件内容 flush 后原子发布，不宣称 Windows 具有相同的目录元数据断电持久性。
ACL 是实际权限边界，Doctor 的可写性是提示；不能用管理员身份或跳过检查掩盖失败。

必须保留以下待验，不将其计为完成：

1. 客户 Windows 10/11 桌面上实际安装/更新、打开新任务后技能加载。
2. Windows Codex 宿主中 GIT/NONE 的原生智能体完整生命周期、失联/中断恢复；
   编排 CLI 的测试字符串不是运行时身份真实性证明。

客户桌面测试请使用专用测试账号/临时项目，不在生产项目上做故障注入：

```powershell
py -3 --version
codex --version
py -3 plugins/project-workflow/scripts/project_workflow_doctor.py --repo . --json
py -3 scripts/check_platform.py
```

在已授权安装/更新的测试配置中使用源码本地安装器，然后新建 Codex 任务，分别在
Git 仓库及无 Git 目录完成一次“规划→用户确认→实现→失败验收阻断→通过验收→完成”，
并检查中文/英文状态。对批准的多智能体计划记录实际 native spawn 返回的身份、
激活、交接及完成；中断一个 Worker 后验证按停止证据恢复而非伪造继续运行。
归档 Windows 版本、Python/Codex 版本、本地文件系统类型、Doctor 与测试日志。
