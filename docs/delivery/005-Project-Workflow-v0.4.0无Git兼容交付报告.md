# Project Workflow v0.4.0 无 Git 兼容交付报告

## 1. 交付结论

Project Workflow v0.4.0 已将 Git 从隐含必需条件改为可配置能力。新建计划支持 `AUTO`/`GIT`/`NONE`，历史计划缺少 VCS 字段时按 `AUTO` 解释且不强制重写。源码语义版本保持 `0.4.0`。

## 2. 主要行为

- `AUTO`：当 Git 可用且目录为有效工作树时解析为 `GIT`，否则解析为 `NONE`。
- `GIT`：显式要求 Git；命令缺失或非工作树时在执行前阻断。
- `NONE`：不执行任何 Git 命令，使用确定性 SHA-256 文件基线记录新增、修改、删除和越界写入证据。
- 执行、恢复和完成入口会重新解析 VCS；审批后的环境漂移会阻断，不会静默换用另一套证据模型。
- `FULL + NONE` 只在 `rollback_strategy`、`rollback_evidence` 非空且 `rollback_verification: "VERIFIED"` 时允许进入执行。文件哈希清单不被当作备份或回滚点。
- `NONE` 多智能体仅使用共享工作区和不重叠写入范围；需要 Git worktree 隔离的任务退化为串行。

## 3. 安全与兼容边界

- 文件快照排除 `.git`、工作流内部状态、IDE 与常见缓存。
- 符号链接仅哈希链接目标文本，不跟随到工作区外读取内容。
- 基线采用临时文件与原子替换；失败时保留旧基线。
- 快照 CLI 输出路径受限于 `.codex/project-workflow/`。
- 本轮未改变插件 ID，未提交、未打 tag、未推送、未部署。

## 5. 使用说明

有 Git 的开发仓库可继续使用 `AUTO`。压缩包、普通目录或已明确不希望 Project Workflow 访问 Git 的场景可使用 `NONE`。对需要数据迁移、安全敏感改造或高风险回滚的 FULL 任务，应先提供并验证 Git 以外的等价回滚能力，否则工作流会正确阻断。
