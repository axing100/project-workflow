# Project Workflow v0.5.0 状态体验与内部锁交付报告

## 交付结果

本次改造已完成，插件源码版本升级为 `0.5.0`。计划文档旁不再生成内部锁文件；任务实现与验收状态分开保存并由内部状态生成 Markdown 视图；展示支持简体中文与英语，其他语言回退英语；v0.4 及更早计划保持可读并支持显式保守迁移。

## 主要能力

- 显式仓库上下文的生命周期锁进入 `.codex/project-workflow`，无仓库兼容命令使用权限受限的临时锁。
- `cleanup-legacy-lock` 只在旧锁未被持有时显式清理，不自动删除潜在活动锁。
- 新增 `project-workflow/task-state/v1`，独立记录实现、验收、证据、阻塞原因、依赖和 CAS 版本。
- 固定展示符号：⚪、🔵、🟡、✅、❌、⛔、➖；中文显示中文标签，英语显示英语标签。
- Markdown 渲染只替换受控块，重复渲染字节级幂等，不解析自由文本、Emoji 或验收复选框。
- 生命周期最终门禁要求所有实现完成且所有适用验收通过，并绑定接受的任务状态版本。
- Doctor 能检查任务 CLI、任务状态完整性和完成版本绑定；旧无状态计划显示为可迁移。

## 兼容与迁移

- v0.4 `[ ]` → 实现未开始、验收未开始。
- v0.4 `[~]` → 实现进行中、验收未开始。
- v0.4 `[x]` → 实现完成、验收通过，并写入迁移证据。
- v0.4 `[!]` → 实现阻塞、验收阻塞。
- v0.4 `[-]` → 实现完成、验收不适用。
- 未迁移旧计划继续按旧生命周期契约运行；未知 schema、状态和未来契约失败关闭。

本仓库的 007、008、009 三个遗留相邻锁已在确认无人持有后通过新命令清理。本 009 计划已作为中文双状态自举样例迁移。
