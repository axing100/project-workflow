# Project Workflow 主动多智能体调度引擎交付报告

## 交付结果

Project Workflow 已从“多智能体使用规范”升级为计划驱动的主动调度引擎。插件会在规划阶段选择 `SINGLE_AGENT`、`AUTO_MULTI_AGENT` 或 `MANUAL_MULTI_AGENT`，并在用户批准计划后，按持久化 DAG、字面量写入范围、Worker 上限和重试边界调度 Codex 原生子智能体。

## 主要变更

- 新增 `scripts/orchestration_state.py`，支持 `validate`、`ready`、`assign`、`complete`、`release`、`block` 和 `inspect`。
- 新增 orchestration companion JSON 协议，校验 plan ID/revision、依赖环、写入范围冲突、Worker 上限、计划 Owner 和最大尝试次数。
- plan 技能会选择并持久化执行模式、拓扑、并行 wave、写入范围和 Agent eligibility。
- execute 技能会主动执行 assign/spawn/wait/verify/retry 循环，只使用当前 Codex 任务的原生协作智能体。
- 入口技能继续只接管复杂任务，并阻止其他同类工作流创建竞争性的调度拓扑。
- 中英文 README 和插件元数据升级到 0.3.0，说明 UI、权限与降级边界。

## 权限与限制

- 用户批准计划只授权计划记录范围内的原生子智能体委派。
- 用户在交付后通过 `帮我提交并推送到远端` 明确授权 Git 提交及推送到当前 `origin/main`。
- Tag、Release、部署和破坏性操作仍未授权，也未执行。
- 插件不能创造 Codex 运行时没有提供的子智能体能力或 UI；不可用时记录原因，并在安全范围内由协调者串行接管。
- AUTO 模式至少需要两个安全且互不冲突的就绪任务才创建 Worker；实际并发还受计划上限和运行时槽位限制。
