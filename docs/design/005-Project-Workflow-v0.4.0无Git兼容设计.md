# Project Workflow v0.4.0 无 Git 兼容设计

## 1. 背景

Project Workflow 的生命周期、审批、调度和状态文件只依赖文件系统，但现有技能把 Git 状态、diff、分支、worktree 和回滚作为默认执行证据。结果是在空目录、解压源码、受限构建环境或未安装 Git 的环境中，核心工作流可以运行，执行体验却会在 Git 命令失败后临时降级，缺少稳定契约。

## 2. 目标

- Git 从隐含必需条件改为显式、可检测、可验证的能力。
- 新计划支持 `AUTO`、`GIT`、`NONE` 三种 VCS 模式；历史计划保持兼容。
- 无 Git 时继续提供审批、任务 DAG、多智能体写入范围隔离、测试、文件变更证据和交付报告。
- FULL 工作流在没有 Git 或等价回滚保障时安全阻断，不用文件哈希冒充可恢复备份。
- 不改变 `project-workflow/v1` 与 `project-workflow/orchestration/v1` 标识，不强制迁移历史文件。

## 3. 非目标

- 不在 v0.4.0 内支持 Mercurial、SVN 等其他 VCS 命令适配器。
- 不实现完整文件备份系统，也不自动复制大型工作区。
- 不把文件哈希清单描述为回滚点。
- 不在无 Git 模式模拟 commit、branch、tag、push 或 worktree。
- 不放宽提交、推送、部署或破坏性操作的独立授权要求。

## 4. 模式契约

新计划允许记录：

```yaml
vcs_mode: AUTO
resolved_vcs_mode: GIT
```

- `AUTO`：规划时检测当前环境；有效 Git 工作树解析为 `GIT`，否则解析为 `NONE`。
- `GIT`：必须存在可执行 Git 且目标目录属于有效工作树，否则 Doctor 和执行入口阻断。
- `NONE`：禁止工作流执行 Git 命令，即使目录碰巧属于 Git 工作树。

历史计划缺少 `vcs_mode` 时按 `AUTO` 读取，但不只为补字段而重写。新计划在请求确认前持久化 `resolved_vcs_mode`，执行、恢复和交付时重新检测；解析结果变化属于环境漂移，必须先阻断并说明影响，不能静默切换证据模型。

## 5. Doctor 契约

Doctor 的 JSON 输出新增稳定的 `version_control` 对象：

```json
{
  "requested": "AUTO",
  "resolved": "GIT",
  "git_available": true,
  "git_worktree": true,
  "rollback_capable": true,
  "status": "OK"
}
```

Doctor 不通过 shell 拼接调用 Git；使用参数数组、短超时和稳定错误码。`AUTO` 未检测到 Git 时返回 `NONE/OK`，不产生噪声。显式 `GIT` 但能力缺失时返回 blocker。显式 `NONE` 不探测或执行仓库变更命令。

规划阶段没有计划文件时，Doctor 只报告环境探测结果；传入计划后校验请求模式、已解析模式与当前环境是否一致。

## 6. 无 Git 变更证据

新增确定性文件系统快照辅助命令，在执行开始前生成内部基线，在交付时比较：

- 记录仓库相对路径、文件大小和 SHA-256；不记录文件正文。
- 默认排除 `.git/`、`.codex/project-workflow/`、Python/IDE 缓存和插件声明的临时产物。
- 路径必须保持在工作区内，不跟随逃逸工作区的符号链接。
- 比较结果稳定输出 `added`、`modified`、`deleted`，并校验任务 `write_scope`。
- 状态保存在 `.codex/project-workflow/<plan-id>/filesystem-baseline.json`，是内部证据而非用户审阅文档。
- 清单只能证明变化，不能恢复内容；交付报告必须明确这一限制。

Git 模式继续以 Git diff/status 为主要证据，不额外生成全工作区哈希清单。NONE 模式不得创建分支或 worktree，多智能体仅允许共享工作区中的不重叠写入范围；需要隔离 worktree 的任务自动退回串行。

## 7. 回滚与级别约束

- LIGHT：允许 NONE，以测试和文件变更清单验收。
- STANDARD：允许 NONE，必须生成基线与最终差异清单，并披露没有 Git 级回滚。
- FULL：只有计划记录并验证了等价回滚来源时才允许 NONE，例如外部环境快照、用户提供的备份或受控的可重建输入；否则执行入口阻断。
- 数据迁移、安全整改或潜在数据丢失任务：没有可验证回滚能力时始终阻断，不因用户选择 NONE 自动放宽。

`rollback_strategy` 是人类可读且需验证的计划字段；非空字符串本身不代表已具备回滚能力。验收证据必须说明恢复来源、恢复步骤和验证结果。

## 8. 迁移状态矩阵

| 旧状态/环境 | 新解释 | 行为 |
| --- | --- | --- |
| 历史计划无 VCS 字段，Git 工作树有效 | `AUTO -> GIT` | 保持原 Git 证据流程，不改写历史计划。 |
| 历史计划无 VCS 字段，非 Git 目录 | `AUTO -> NONE` | 使用文件快照证据；FULL 无回滚来源时阻断执行。 |
| 新计划 `AUTO/GIT`，执行时 Git 仍有效 | 保持 `GIT` | 正常继续。 |
| 新计划 `AUTO/NONE`，执行时仍无 Git | 保持 `NONE` | 正常继续文件快照流程。 |
| 已批准 `AUTO/GIT`，恢复时 Git 消失或工作树损坏 | 环境漂移 | 阻断并要求恢复环境或修订计划，不静默切换 NONE。 |
| 已批准 `AUTO/NONE`，恢复时出现 Git | 环境漂移 | 仍阻断并要求确认是否修订，避免中途改变证据基线。 |
| 显式 `GIT` 且 Git 不可用 | 无合法映射 | Doctor blocker，不写部分状态。 |
| 显式 `NONE` 且目录是 Git 工作树 | 保持 `NONE` | 不调用 Git；文件清单排除 `.git/`。 |
| 未识别 VCS 值 | 拒绝 | 稳定错误，不默认猜测。 |
| 重复探测/重复快照比较 | 幂等 | 同一内容得到稳定结果，不重复扩大状态。 |
| 快照写入中崩溃 | 保留旧基线 | 临时文件原子替换，不留下半份 JSON。 |
| 活跃 Worker 恢复时 VCS 解析漂移 | 阻断调度 | 先停止新分配并核对已有写入，再决定恢复或修订。 |
| 缺失/过期租约 | N/A | 当前协议没有租约；继续用原生 runtime 身份和 roster 对账。 |
| 回滚到 v0.3.0 | 忽略新字段 | v0.3 继续使用原 Git 假设；无 Git 用户应改用 v0.4。 |

## 9. 安全与性能

- 快照计算必须有明确排除项和可选写入范围，避免无界遍历依赖缓存或大型构建产物。
- 符号链接只记录链接自身或拒绝逃逸目标，不读取工作区外内容。
- Git 探测错误不泄漏完整环境变量或内部堆栈。
- 文件清单中不得写入文件内容、凭据值或工作区外绝对路径。
- 多智能体仍由调度器强制不重叠写入范围；NONE 模式不能宣称具备 worktree 隔离。

## 10. 验收标准

1. 普通目录且系统没有可用 Git 仓库时，AUTO 正确解析为 NONE，Doctor 返回 OK。
2. 显式 GIT 在非 Git 环境稳定阻断且不产生部分状态。
3. 显式 NONE 在 Git 仓库内也不会运行 Git 证据命令。
4. 文件快照稳定识别新增、修改、删除和范围越界，且不跟随逃逸符号链接。
5. FULL + NONE + 无等价回滚证据时执行被阻断。
6. 历史计划和历史调度状态继续通过兼容测试。
7. Git 环境原有流程、81 项插件回归和 6 项安装器回归不退化。
